Rules I work by

Four things that decide the shape of every build.

  1. .01

    Root cause over patches

    Three fixes that do not hold mean the model is wrong, not the code. I stop and re-read the architecture.

  2. .02

    Deterministic where it counts

    The model reads and classifies. Code assembles and reproduces. The same input gives the same file, every time.

  3. .03

    The human gate is a feature

    A system that says “I am not sure” is worth more than one that is always confident and sometimes wrong.

  4. .04

    Design is part of the system

    If the screen hides what the system knows, the architecture failed — no matter how clean the pipeline is.
